Tutorial: how to use this tool, and in what order to set up a new robot

Before you start

  • The computer can ssh to the robot without a password (for example orangepi@duck-1a2b.local or orangepi@<robot IP>). Give it with --host at start.
  • Turn the robot on, let it join WiFi, then click Refresh. The header shows the host name and the robotd state. If it cannot connect, it tells you; common causes are: the robot is off, WiFi dropped, or the IP changed.
  • The red Relax all button at the right of the header works at any time: if robotd is running, it tells robotd to relax; if not, it broadcasts "torque off" on the bus directly. If a servo moves wildly, gets hot or smokes, press it first, then cut the power.

Stopping robotd does not relax the servos. If the robot is standing, make it sit or lie down first, or press Relax all, then stop robotd.

Recommended order for a newly built robot

  1. Servo setup (before they go into the body, with the USB board on the "Servos" tab): change each ID, switch to 500k, center it, then fit the horn.
  2. Board power-up check: when the soldering shop delivers, measure everything once per the test notes (diode mode, shorts); clean the servo sockets first, then measure V–GND and DATA–GND.
  3. IMU firmware: on a new PDB, flash the IMU with an ST-Link first ("IMU firmware" tab).
  4. Robot test: after assembly, run all six items on the "Robot test" tab; continue only when all pass.
  5. Joint mapping: on the "Servos" tab, use the "Joint mapping" card to wiggle each servo and click its joint, then change IDs to match or write joint_ids (the "Joint mapping" table on the right is joint_ids from the config).
  6. Zero calibration: on the "Zero calibration" tab, set directions and zeros, then fine-tune while standing on home.
  7. Last, run "Servo bus" once more and export the report to keep.

USB debug board

New servos ship at 1M baud. When the OPi UART is set to 1M, it really runs at 750k, so new servos can only be set up through the Raspberry Pi test bench or the Feetech USB debug board (CH343). For the USB board: Plug it into the computer, pick its serial port on the right (marked "CH34x" in the list), and click Use this port. If the FD software is open, it holds this port; close FD first.

Tutorial: new servo setup, check after assembly, joint mapping, common faults

A. New servo setup: use the "New servo batch setup wizard" card (factory ID 1, 1M, before they go into the body)

  1. On the Overview tab, pick the USB debug board's serial port (the one marked "CH34x"; close the FD software first). Give the debug board servo power: HD-1910 uses 2S, never connect 3S; HL-2915 uses 3S.
  2. Pick the servo model in the wizard. It sets the unload condition and the current unit: HD-1910 writes 5 (0x05), 0.65 mA/count; HL-2915 writes 13 (0x0d), 6.5 mA/count.
  3. Pick the wiring:
    • Daisy chain (recommended): set the ID order to 15-1. All new servos are ID 1. Giving numbers in reverse order makes sure that at any time only the servo just connected is ID 1, so the ones already set up can stay connected (same as tools/servo/setup_ids.py).
    • One at a time: any ID order, for example 1-15; unplug each servo when it is done.
  4. Click Start, then for each servo follow the prompts:
    1. Connect the servo and click Connected, detect. The wizard looks for ID 1 at 1M and 500k.
    2. When found, it sets it up: changes the ID; writes limits 0/4095; writes mode 0 (HD-1910 ships with 4); writes the unload condition; switches to 500k and locks; finally reads back to check.
    3. For the first servo it asks you to power-cycle it, to confirm the settings were really saved to EEPROM.
    4. Center and hold: the servo turns to 2048 and holds torque. Now fit the horn at the neutral position, then click Horn fitted, release torque.
  5. If it stops halfway, that is fine: click Start again. Servos that already got their new ID are recognized ("ID n already has a servo") and set up again in place, with no ID clash.
  6. When all are done, click Check whole chain to scan once at 500k.
  7. Messages you may see while detecting:
    • "Several servos answered": more than one new servo was connected, or two servos are both ID 1; unplug the extra one;
    • "A servo set up earlier does not answer": something in the chain is loose;
    • "Not found": check the power, the direction of the 3-wire cable, and that the plug is fully in.

You can also do it by hand: scan below, click a row, use the "Change ID / Change baud / Center" buttons, or change 33, 9/11, 19 in the register table. All input boxes take decimal numbers. Center only servos that are not yet in a joint; centering after assembly turns the joint to its middle.

B. Check after assembly (robot bus)

  1. Stop robotd on the Overview tab. Set bus to "Robot", baud 500k, ID 0–20, tick "Include 200", and click Scan. You should see 15 servos and the IMU board (200).
  2. Watch for red text in three places:
    • Red position: the reading is outside 0..4095, which is a multi-turn count (the joint was forced too far). Rebooting the OPi does not clear it; cut power to the servos. Until then the tool refuses to turn on its torque. If after a power cycle the reading at the joint's zero is still near 0 or 4095, use "Set current position as center" in D below to move the wrap point away.
    • Status not 0: the servo reported over-voltage, under-voltage, over-temperature or over-current; check the battery and the temperature.
    • Missing ID: first check that channel's cable and socket (clean the flux paste off the PDB sockets after soldering; leftover flux conducts), then check for an ID clash.
  3. The voltage column also shows the battery: a full 2S is about 8.4 V, 3S about 12.6 V.

C. Joint mapping: the servos were not fitted in ID order

  1. Lay the robot flat or hold it in your hands, legs in the air. Use the robot bus (stop robotd first) or the USB debug board (connected to the robot's servo bus; if the main board is on, stop robotd too). Set "Bus / Baud" below (fitted servos are usually 500k), and pick the right servo model (it sets the current unit and the current limit).
  2. Click Scan and start: it scans ID 0–39, then wiggles ±8° starting from the lowest ID. See which joint moves and click it in the joint table; the next servo starts to wiggle on its own. If you missed it, click Wiggle again. If you clicked the wrong joint, click that servo's ID tag above, let it wiggle again, then click the right joint (the ID that held that joint goes back to unassigned). Refreshing the page halfway does not lose your work.
  3. After all 15, click Left/right check: for each pair of matching leg joints it wiggles the left one and then the right one, then neck, head and mouth one by one; the button of the joint that is moving gets a frame. Left and right are the easiest to get backwards (during the HL-2915 robot's calibration, looking at one side alone went wrong four times), so do not skip this step.
  4. Then pick one of two:
    • A. Change IDs to match: pick a target order (joint order 1–15, same as the HL-2915 robot, the current config, or custom) and click Change IDs. It first moves every servo that changes to a temporary ID of 160 + new ID, then to the new ID, so swapping two servos works too. If it stops halfway, any 16x / 17x IDs you see in a scan are temporary; subtract 160 to get the ID it should have. After that, write the new order into the config (if you did it on the robot bus, a button writes it for you).
    • B. Keep the IDs: write the shown joint_ids = [...] into the robot config (it is backed up first as .bak-TIME). If you did it on the USB debug board, copy that line into the [bus] section of the toml.
    Either way, restart robotd for it to take effect. joint_signs / joint_offsets are stored per joint, not per ID; after mapping, calibrate them on the Zero calibration tab as usual.

C2. Single servo wiggle test

  1. Hold the robot in your hands or lay it flat, legs in the air with no load. Click a row; the current limit defaults to 400 mA and the swing to ±6°. Click Wiggle test and confirm in the dialog.
  2. See which joint moves on the robot and compare it with the "Joint" column. If the whole robot does not match, use the "Joint mapping" card above; if only one or two are off, you can also swap IDs here. On the HD-1910 robot, the neck pitch and head pitch were found this way, swapped compared to the HL-2915 robot.
  3. The "target → actual (error)" values in the result should be within ±2.5°. In the small chart below, the blue line is position and the orange line is current. If it does not reach the target: first check whether 44 (goal current) or 46 (speed) was written as 0, then check for a mechanical jam.
  4. Direction (which way is positive) is not checked here; check it joint by joint on the Zero calibration tab.

D. Set current position as center (the servo's own position correction, EEPROM 31)

  • What it does: stores the servo's current position as 2048; from then on, reading = raw reading − offset (mod 4096). The wrap point between 0 / 4095 moves to the back of the output shaft, and goal positions shift with it.
  • When to use it: a servo whose horn was not fitted at center, or a fitted servo whose reading at the joint's zero is near 0 / 4095 (like the head roll of the HD-1910 robot reading 4140). No need to remove the horn: turn torque off, move the joint to zero by hand, click a row, then click Set current position as center.
  • Cost: if the joint was already zero-calibrated, the joint_offsets value of this servo is no longer valid; calibrate it again on the Zero calibration tab (after that, its offset should be near 0).
  • Tested (10-31, HL-2915, firmware 3.45): the value written to 31 stays after a power cycle; turning by hand past the old wrap point gives continuous readings; centering and wiggle both reach the target in the new coordinates. The STS series one-step correction "write 40 = 128" does nothing on it. HD-1910 is not tested yet; the first time, try it on a spare servo on the bench.

E. Common faults

  • Torque is on but it does not move at all, current 0: 44 (goal current) or 46 (speed) is 0. HD-1910 sometimes also gets "stuck at zero current"; writing 46 again makes it move. The tool writes 42..47 together every time it writes a goal.
  • Loses strength while running, torque enable still 1: over-current unload; turn off bit3 of 19 (write 5 for HD-1910).
  • Current shows 10 times too high or too low: the "Current unit" above is wrong. HD-1910 is 0.65 mA/count, HL-2915 is 6.5 mA/count.
  • Cannot find the servo after changing the baud rate: power-cycle the servo, then scan at the new baud rate.

New servo batch setup wizard (USB debug board)

Connect them one by one: change ID, set EEPROM, switch to 500k, then turn to 2048 to fit the horn (the servo's own "zero"). The joint zero after assembly is done on the "Zero calibration" tab.

Joint mapping (after assembly: which ID is in which joint)

Wiggle them one by one and click the joint that moves. When all 15 are done, you can change the servo IDs to the order you want, or write the mapping straight into joint_ids in the config. It uses the bus chosen in "Bus / Baud" below; for the robot bus, stop robotd first. Left and right mean the robot's own left and right.

Wiggle: swings ±swing around the current position, goes back, then turns torque off; a side that would cross 0/4095 is skipped; over-current (default 1.5 A) or more than 15° off cuts torque at once. Center: turns to the nearest 2048 in the same turn and holds torque; fit the horn, then release. Only for servos not yet in a joint. Any reading outside 0..4095 (multi-turn) is refused torque; cut the servo power.
Tutorial: zero calibration (joint_signs / joint_offsets)

The calibration page (the embedded tools/joint_align below) puts the robot's live joint angles on the training model, so you can compare with the model to check directions and record zeros. The result is two lines in the toml [bus]: joint_signs (which way each joint turns for positive) and joint_offsets (the encoder reading at zero minus 2048).

Preparation

  1. The servo bus check passes: all 15 answer, no multi-turn readings (red position).
  2. Start robotd on the Overview tab.
  3. The robot lies flat or is held in your hands: after you click Start calibration, the whole body relaxes.

Step 1: check directions (torque off, move by hand)

  1. Click a joint in the table and see which way its positive direction turns in the third view.
  2. Move that joint on the robot by hand in the same direction. The model in the first two views should turn the same way, and the reading should go up.
  3. If the direction is wrong, click Reverse on that row (it takes effect at once), then move it again to confirm.
  4. Do this for all 15 joints. For left/right pairs, move both sides at the same time; moving only one makes it easy to read it backwards. The mouth has no model: opening it should make the reading go up.

Step 2: record zeros

  1. Set "Reference" to Zero and pose the robot like the reference picture (legs straight, head level).
  2. When the whole body is posed, click Set all to zero, or select one joint and click Set selected joint to zero. Close the mouth fully before setting its zero.
  3. Click Write config: it backs up first (*.bak-TIME), changes these two lines in , then restarts robotd.

Step 3: fine-tune while standing on home

  1. Hold the robot and click Write and go home: robotd restarts (torque stays on) and the robot moves smoothly to the standing pose home.
  2. Put it on the table and check:
    • the soles are flat;
    • torso pitch and roll are near 0 (IMU readings are at the top of the page; measure the torso with a phone level app to check that the IMU is right);
    • the head is parallel to the ground;
    • the toes point straight ahead;
    • left and right are symmetric;
    • it stands on its own.
  3. If a joint is off, click −/+ on either side of that row's zero (0.5° each, so at the same command angle the joint turns more in the negative / positive direction), then click Write and go home to see the result.
  4. Lessons learned (HD-1910 robot, 10-25):
    • Feet are flat but the torso still leans forward: work out the hip, knee and ankle corrections from the real angles of the shin and thigh.
    • Torso is level but the robot falls backward: the neck and head tilt-back angles are wrong; measure them and fix them.
    • Still falls backward after that: the real robot's center of mass is further back than the model's; change the training model, and do not touch the zeros again.
  5. Values that are changed but not yet written show in orange. Undo changes goes back to the values robotd uses now.
Uses tools/joint_align: renders the robot's live joint angles on the training model; each joint can be "reversed", "set to zero", or fine-tuned by ±0.5°. "Write config" backs up first, then changes joint_signs / joint_offsets in on the robot, then runs ; "Write and go home" also runs .
Needs robotd running. The first connection sends robot.relax (the whole body relaxes), so lay the robot down or hold it first. Zero reference: pose thigh, shin and torso like the "zero reference" picture on the page; standing on home, the soles are flat and IMU torso pitch ≈ 0.
Tutorial: flash the firmware of the IMU board on the PDB

The STM32G031 + LSM6DSV16X on the PDB runs firmware/imu-feetech. On the servo bus it acts as Feetech device ID 200 (500k), and robotd reads it every tick together with the 15 servos. A newly soldered PDB comes blank and must be flashed once; flash it again here when the firmware changes.

Wiring

  • Plug the ST-Link into the computer. The first time, install the WinUSB driver for it with Zadig, or probe-rs will not find it.
  • Connect to J2 on the PDB: 1 SWDIO, 2 SWCLK, 3 GND, 4 3V3. If the PDB is already powered by a battery or a supply, 3V3 can be left off.
  • ST-Link 10-pin header (Zave): 2 SWCLK, 4 SWDIO, 6 GND.

Steps

  1. 1. Build: cargo build --release. "Build output" on the left shows whether it is older than the source. If "Uncommitted changes" is not empty, what you flash is not the version of any commit.
  2. 2. Find ST-Link: probe-rs list; the output must have an ST-Link line. If it shows "No debug probes were found", check the USB cable and the WinUSB driver.
  3. 3. Flash: probe-rs download --verify plus reset. The output should end with "done".
  4. 4. Check over the bus (stop robotd on the Overview tab first). It passes when:
    • the model is 0x16D6, and the firmware version matches the source;
    • the fused output is about 120 Hz, flags = 3;
    • gyro noise is < 1 dps when lying flat and still;
    • pitch and roll match the robot's real pose.

If it will not flash

  • Cannot connect to the chip (SWD reads nothing, SWDIO on J2 is 0 V): first check the U1 orientation; the dot should be at the bottom left (the first PDB had it soldered the wrong way). Then check that the PDB has power, and check the J2 wire order.
  • No 200 on the bus after flashing: check the bus harness from the PDB to the HAT; make sure the robotd config has [bus] imu = true. The IMU must be last in the SYNC_READ; robotd already orders it that way.
  • Pitch and roll axes do not match: the IMU mounting direction is set by [bus] imu_axes (both the HD-1910 and the HL-2915 robots use "y,x,-z"). To check, lay the robot on its back and see which sensor axis gravity falls on.

Firmware firmware/imu-feetech

Plug the ST-Link into the computer and connect it to J2 on the PDB (1 SWDIO, 2 SWCLK, 3 GND, 4 3V3; if the PDB is powered, 3V3 can be left off). On Windows, install the WinUSB driver for the ST-Link with Zadig first. New PDB: the U1 dot is at the bottom left; if it is soldered the wrong way, SWD reads nothing.
